# Модуль поиска `retrieval.py`

Ищет по базе знаний Energytool и возвращает самые подходящие фрагменты. Ответы не генерирует,
диалоги не хранит, заявки не собирает: только поиск.

## Как подключить (из `solution.py`)

```python
from retrieval import Retriever

retriever = Retriever()                  # ОДИН раз при запуске (~1–3 с с прокси)
result = retriever.retrieve(question)    # на каждый вопрос
```

`question` может быть одной репликой или диалогом целиком в формате тестов:
`Пользователь: ...\nАссистент: ...\nПользователь: последний вопрос`.
Историю можно передать и отдельно:
`retriever.retrieve("Сколько это стоит?", history=[{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}])`.

## Что возвращает `retrieve`

```python
{
  "query": "...",           # по какому тексту искали (для отладки)
  "mode": "dense",          # "dense" — смысловой поиск; "bm25" — запасной; "local" — только разработка
  "confidence": 0.56,       # сходство лучшего фрагмента, 0..1; None в режиме bm25
  "no_answer": False,       # True — в базе подходящего нет (confidence < 0.50) или вопрос пустой
  "search_ms": 309,         # время поиска в мс
  "chunks": [               # лучший первым, по умолчанию 5 штук
    {"id": "solar-010", "topic": "solar", "product": "solar",
     "path": "Солнечные электростанции под ключ › Размещение",
     "score": 0.56, "guard": False, "text": "..."},
    ...
  ],
  "guards": [               # защитные блоки найденного продукта (того же формата, score = None)
    {"id": "orem-026", "path": "... › Чего утверждать нельзя", "text": "...", ...}
  ]
}
```

- `guards` — блоки «Чего утверждать нельзя», «Что мы не делаем», границы продукта, «Не подходит, если»
  для продукта, который нашёлся первым (если их ещё нет в `chunks`; порядок: сначала «нельзя утверждать»).
  Пусто при `no_answer`. Нужны, чтобы модель не пообещала лишнего (например, гарантированную экономию).
  Объём до ~2,5 тыс. символов; если место в промпте ограничено, можно взять первые один–два блока.
  Не нужны — игнорируйте поле или выключите `RETRIEVER_GUARDS=0`.
- `guard: True` — защитный блок («Не подходит, если», «Чего утверждать нельзя», «Что мы не делаем»).
  Модели полезно показывать такие блоки вместе с остальными.
- `no_answer` — только сигнал. Что ответить клиенту, решает бот. Порог мягкий: он отсекает явно
  посторонние вопросы (погода, рецепты), но не вопросы «рядом с темой» (например, ветряная
  электростанция): для них нужно правило в промпте «если во фрагментах нет прямого ответа, откажись».
- Для режима отладки в интерфейсе: `chunks[i]["id"]`, `["path"]`, `["score"]`, `search_ms`.

## Что положить в ZIP

Только корневые файлы (вложенные папки платформа не переносит):

```
retrieval.py   build_chunks.py   retriever.py   embedder.py   (+ ваш solution.py, requirements.txt)
```

В `requirements.txt` нужны `numpy==2.2.6` и `httpx==0.28.1` (обе из разрешённого набора).
Базу знаний в ZIP класть не надо: модуль сам читает `DATA_DIR/knowledge-base.zip`, режет её на
фрагменты и строит индекс при запуске.

## Переменные окружения (все необязательные, задаёт платформа)

| Переменная | Что делает |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `EMB_MODEL` | адрес, ключ и модель эмбеддингов (bge-m3) на прокси платформы |
| `DATA_DIR` | где лежит `knowledge-base.zip` (по умолчанию `data`); `KB_PATH` — прямой путь к ZIP или папке |
| `TOP_K` | сколько фрагментов отдавать (5) |
| `RETRIEVER_THRESHOLD` | порог `no_answer` (0.50) |
| `RETRIEVER_MODE` | принудительный режим: `dense` / `bm25` |
| `RETRIEVER_DEBUG=1` | на каждый вопрос строка в stderr: режим, уверенность, `no_answer`, время, id фрагментов и защитных блоков. Включите на первом сабмите, чтобы увидеть, что на платформе работает `dense`, а не запасной `bm25` |
| `RETRIEVER_GUARDS=0` | не добавлять поле `guards` (оно будет пустым) |

Если прокси недоступен при запуске или на отдельном вопросе, модуль сам переходит на BM25 (без
внешних вызовов); в `result["mode"]` будет `"bm25"`, а `confidence` — `None`.

## Как запустить самостоятельно

Все команды выполняются из папки `rag`. Рядом с ней должны лежать папка `knowledge-base/` и файл
`demo_questions.csv` (как в папке проекта); иначе задайте `KB_PATH` (путь к папке или ZIP базы).
Нужен Python 3.10+ и `pip install numpy==2.2.6 httpx==0.28.1`.

**Найти фрагменты для одного вопроса** (результат в формате JSON, как в разделе выше):

```bash
python retrieval.py "Сколько стоит поиск потерь?" --mode bm25 --short
```

`--mode bm25` работает без моделей и ключей (качество ниже). Режим `dense` ходит на прокси за
эмбеддингами, ему нужны переменные окружения:

```powershell
$env:LLM_BASE_URL = "https://адрес-прокси/v1"      # PowerShell (Windows)
$env:LLM_API_KEY  = "ваш-ключ"
python retrieval.py "Сколько стоит поиск потерь?" --mode dense --short
```

(в bash: `export LLM_BASE_URL=...` и `export LLM_API_KEY=...`). Режим `local` запускает bge-m3 на вашем
компьютере: нужен `pip install sentence-transformers` и около 2,3 ГБ на диске для модели. Он нужен
только для разработки.

**Посмотреть, как база нарезана на фрагменты** (создаст `chunks.json` и `chunks_report.txt` с
отчётом и проверкой чисел):

```bash
python build_chunks.py ../knowledge-base chunks.json
```

**Проверить качество поиска** (три набора вопросов: выданные 18, наши 31, наши диалоги 8):

```bash
python evaluate.py                          # только BM25, без моделей; подбор параметров BM25
python evaluate_retrieval.py --mode bm25    # то же через retrieve(), без моделей
python evaluate_retrieval.py --mode dense   # эмбеддинги через прокси: сравнение способов учёта диалога
python measure_scores.py --mode dense       # уверенность поиска у вопросов с ответом и без него (порог отказа)
```

Если выбранный режим не запустился (например, нет ключа), скрипты проверки останавливаются с
сообщением, а не подменяют эмбеддинги тихим BM25. Файлы `eval_*.json` — проверочные вопросы с эталонными
фрагментами (`тема|часть заголовка`); добавляйте свои в `eval_own.json` или `eval_dialogs.json`.

## Проверка и ограничения

Локальная проверка BM25 через `python -m rag.evaluate_retrieval --mode bm25` на текущих наборах дала:

| Набор | Вопросов | hit@1 | hit@5 | MRR |
|---|---:|---:|---:|---:|
| demo | 18 | 0.50 | 0.67 | 0.593 |
| own | 31 | 0.65 | 0.90 | 0.761 |
| dialogs | 8 | 0.62 | 0.88 | 0.750 |

Результаты зависят от состава документов и контрольных вопросов. Наборы `own` и `dialogs` являются внутренними проверочными данными, поэтому показатели по ним не являются независимой внешней оценкой.

Семантический режим BGE-M3 и API организаторов следует оценивать отдельно после настройки реального адреса сервиса и ключа. Реранкер в текущую версию не включён.
