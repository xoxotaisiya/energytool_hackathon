# Как сохранить результаты проверки бота

Лучший вариант — автоматические `results.json` и `results.txt` в UTF-8.
JSON сохраняет точные поля диагностики, TXT удобен для чтения. Сохраняйте оба
вместе с папкой sessions. Переносить ответы в Word или делать скриншоты не нужно.

## Запуск из PowerShell

Команды ниже выполняются после обычного приглашения
`PS E:\Users\natka\Desktop\project>`, когда интерактивный бот завершён через `/exit`.
Экспортёр использует то же приложение и настройки, что start_energytool.ps1.

Сначала можно посмотреть список без запуска модели:

```powershell
.\test_energytool.ps1 -Group all -List
```

Основные 20 вопросов:

```powershell
.\test_energytool.ps1 -Group basic
```

Все 49 сценариев:

```powershell
.\test_energytool.ps1 -Group all
```

Дополнительные 12 проверок с новыми формулировками, исправлением данных,
отменой звонка, границами мощности и предметом цены:

```powershell
.\test_energytool.ps1 -Group all -Scenarios .\bot_checks\validation_2026_11_16.json
```

Этот набор не является независимым скрытым экзаменом после первого разбора:
при исправлениях по его результатам он становится регрессионным. Для оценки
обобщения нужны следующие, ещё не использованные при доработке примеры.

Полный прогон может занять десятки минут. Для сопоставимых задержек
проверяйте последовательно, без одновременной отправки запросов из других окон.

Отдельные группы:

```powershell
.\test_energytool.ps1 -Group paraphrases
.\test_energytool.ps1 -Group boundaries
.\test_energytool.ps1 -Group dialogues
.\test_energytool.ps1 -Group robustness
```

Выбранные сценарии — например, рост счёта и исправление сведений:

```powershell
.\test_energytool.ps1 -Ids T01,P01,D02
```

Три независимых повтора выбранных сценариев:

```powershell
.\test_energytool.ps1 -Ids T01,P01,D02 -Repeat 3
```

Повторяется весь сценарий, включая многоходовую цепочку. Каждый новый сценарий
и каждый повтор начинают новую сессию. Внутри цепочки сохраняется настоящая
история, включая фактические ответы бота. `/new` внутри D06 отдельно проверяет
сброс сессии. Заранее подготовленные ответы ассистента не используются.

## Где будут результаты

Каждый запуск создаёт уникальную подпапку, например:

```text
project/
  test-results/
    YYYYMMDDTHHMMSSZ-basic-xxxxxxxx/
      results.json
      results.txt
      sessions/
```

Время в имени папки — UTC, суффикс защищает от совпадения имён. Предыдущие
прогоны не перезаписываются. Файлы сохраняются после каждого хода.

Для последующего разбора достаточно оставить папку в проекте и написать
её имя в чате. Основной файл для анализа — results.json. В нём есть:
- ID сценария и номер повтора;
- ожидаемое и запрещённое поведение — только для проверки;
- все реальные вопросы и ответы по порядку;
- session_id, статусы и время;
- источники и полная диагностика приложения;
- состояние клиента и локальной заявки после каждого хода;
- модель, параметры и хеш версии кода.

`completed=true` означает, что запланированные шаги выполнены, а не что
все ответы правильные. При трёх последовательных технических ошибках
экспортёр останавливается и оставляет частичный отчёт. Ctrl+C также
сохраняет уже записанные результаты; проверяйте completed/error_code.

Для контактного сценария D07 используется только тестовый адрес
qa@example.test. Проверяется локальное сохранение, а не звонок или передача в CRM.
Тестовые сессии лежат отдельно от обычных сессий интерактивного бота.

## Если проверять вручную

Откройте [QUESTIONS.md](QUESTIONS.md) или [QUESTIONS.txt](QUESTIONS.txt).
В них вопросы разбиты на готовые блоки с явными `/new`.

1. В PowerShell запустите `.\start_energytool.ps1`.
2. Дождитесь приглашения бота `Вы:`.
3. Вставляйте строки одного блока по одной, дожидаясь ответа.
4. Перед следующим блоком введите `/new`, как указано в файле.
5. Названия сценариев и ожидаемое поведение боту не отправляйте.
6. Сохраните полный вывод вместе с `/new` и JSON-диагностикой в TXT UTF-8.

Группы ID: T — основной набор, P — перефразирования, G — границы,
D — диалоги, R — ограничения. В ручном файле результатов указывайте ID.
Не сокращайте ответ, не исправляйте опечатки и не удаляйте неудачные результаты.
Можно добавить собственную оценку отдельным абзацем после полного вывода.

## Как оценивать

Проверяйте достоверность по базе, полноту, применимость к клиенту, память,
отрицания и следующий шаг. Успешный статус не заменяет проверки содержания.
Список может выявить ещё не исправленные ошибки — он не обещает, что текущий
бот пройдёт каждый случай. Для стабильности сравнивайте все повторы.

Вопросы и критерии хранятся в scenarios.json. Если меняете этот файл,
для обновления ручных файлов запустите build_manual_files.py окружением проекта.
Экспортёр всегда читает JSON; ожидания не добавляются в подсказку LLM или индекс.
