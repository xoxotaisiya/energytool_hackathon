## Быстрый старт: Windows PowerShell, Python 3.11

Из корня этого репозитория после установки Python и Ollama:

```powershell
py -3.11 -m venv .energytool_hackathonapp.venv
.energytool_hackathonapp.venvScriptspython.exe -m pip install -r requirements.txt
Copy-Item .energytool_hackathonapp.env.example .energytool_hackathonapp.env
.start_energytool.ps1 -Pull
```

Последующие запуски: `.start_energytool.ps1`. `/new` — новая сессия,
`/debug` — диагностика, `/exit` — выход. Если PowerShell блокирует скрипты,
следуйте политике выполнения вашей организации; менять глобальную политику
или запускать от администратора для ядра не требуется.

Без сети при уже загруженных моделях используйте обычный запуск без `-Pull`.
Модели и виртуальное окружение не включены в репозиторий.

## Проверка

```powershell
Push-Location .energytool_hackathonapp
..venvScriptspython.exe -X utf8 -m unittest discover -s tests -q
Pop-Location
.	est_energytool.ps1 -Group all
```

Второй запуск использует настоящую модель и сохраняет results.json,
results.txt и sessions в `test-results/`. Готовые вопросы: `bot_checks/`.
Исторический общий набор — 49 сценариев, дополнительный — 12.
Их результаты не являются общей точностью бота или баллом жюри.

## Что находится в репозитории

`energytool_hackathon/app/` — актуальное приложение; `bot_checks/` — сценарии;
`docs/` — передача команде, исходные требования и отчёты. Корневой
requirements.txt содержит только зависимости приложения. Полный разрешённый
организаторами список хранится в docs/reference/allowed_requirements.txt.

Персональные сессии, реальные .env, модели, кеши и окружения исключены.
Демо-вопросы и образцы нужны для проверки и не являются таблицей ответов
при консультации. Публичный интерфейс — EnergytoolAI.chat().

## Границы готовности

Локально проверена qwen3:4b-instruct-2507-q4_K_M с BGE-M3. Платформенная
Qwen3.8-27B ещё не проверена. Контакт сохраняется только локально; полной
заявки с ФИО, компанией и резюме, веб-чата и CRM в этом ядре нет.
Свободный пересказ может быть неполным или стилистически неудачным.
Исходные документы организаторов находятся в docs/reference/.
Сведения о тарифах и продуктах используются из выданной базы, не из интернета.
