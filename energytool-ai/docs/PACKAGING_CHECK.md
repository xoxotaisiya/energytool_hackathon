# Проверка подготовленной копии

Дата: 16 ноября 2026 (Asia/Vladivostok).

Создан самостоятельный корень energytool-ai с приложением
energytool_hackathon/app. Исходная рабочая версия не перемещалась и не
переписывалась. Локальный Git инициализирован с веткой main; коммитов,
удалённого адреса и публикации пока нет.

## Проверено именно в этой копии

- Создано новое виртуальное окружение и установлены зависимости из её
  requirements.txt. В качестве интерпретатора тестов использована новая .venv.
- Все 123 автоматических теста прошли, включая исполнение плоского сабмита
  через управляемый API в отдельном процессе.
- test_energytool.ps1 -Group all -List выводит 49 сценариев.
- Настоящая локальная Qwen проверена на T01, T05, D02, D04, D05: пять
  сценариев, девять ответов, без технических ошибок. T05 использует свободную
  генерацию; остальные проверяют источники, исправление факта, два вида
  мощности и отмену handoff. Это smoke-проверка, не новый полный all.
- Результаты сохранены локально в test-results/20261115T161010Z-all-fdb5393b:
  results.json, results.txt и sessions. Эти файлы исключены из Git.
- При первом построении нового индекса 273 embeddings потребовалось около
  133 секунд на этом компьютере. После создания кеша запуск занял 0,5 с.
  Поэтому на новой машине первый запуск может быть заметно дольше ответов.
- Настоящий запуск root/start_energytool.ps1 через Windows PowerShell
  (powershell.exe) завершён командой /exit с кодом 0, кириллица корректна.
- tools.build_submission создаёт dist/platform.zip: 21 корневой файл,
  63 106 байт. Сборщик теперь читает разрешённый список из docs/reference,
  а не ожидает файлы за пределами репозитория.
- Git исключает .env, .venv, .runtime, .cache, sessions, test-results и dist.
  .env.example, тесты и docs/reports остаются доступными для добавления.

## Что изменено при упаковке

Переименована папка приложения, сохранена двухуровневая вложенность для
корневых скриптов и сценариев. Обновлена документация и путь сборщика к
списку разрешённых зависимостей. Запуск поддерживает обычную установленную
Ollama, свой portable executable или уже работающий сервер. Принудительное
включение Vulkan в общем скрипте убрано: выбор GPU оставлен Ollama.
Код RAG и консультанта перенесён без изменений; его хеш совпадает с финальной
проверенной версией fa694fba58cfc96f54427e35c5793e46ca0a91f4db914d4b9ad26ddf37626f0a.

Для удобства на этом компьютере .env создан из безопасного .env.example,
а .venv установлена локально. Они не являются переносимыми исходниками и
не попадут в Git. Модели не копировались: проверка использовала уже работающий
сервер Ollama на 127.0.0.1:11434. На машине коллеги Ollama и модели нужно
установить отдельно по SETUP.md.

Полного холодного запуска на другом компьютере, прогона платформенной 27B
и проверки UI/полной заявки здесь не было. Общая точность не измерена.
Манифест SOURCE_MANIFEST.json содержит SHA-256 передаваемых файлов, кроме
самого манифеста; сгенерированные и игнорируемые файлы туда не включаются.
