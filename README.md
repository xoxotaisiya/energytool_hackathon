# Energytool — AI-консультант МТС

Локальное терминальное приложение для консультаций по продуктам МТС Energytool. Система использует исходную базу знаний проекта, RAG-поиск и настоящую языковую модель Qwen через Ollama либо совместимый API.

## Состав решения

- **Консультант** — управляет диалогом, определяет задачу клиента, выбирает следующий шаг и формирует ответ.
- **RAG** — извлекает релевантные фрагменты из базы знаний и передаёт их языковой модели как контекст.
- **LLM** — реальная модель Qwen. В рабочем режиме приложение отправляет запросы в настроенный сервис модели. Подменяющая генерацию заглушка в приложении отсутствует.
- **История диалога** — сохраняется локально в JSON и учитывается в последующих сообщениях.
- **Интерфейс интеграции** — предоставляет единый метод `EnergytoolAI.chat()` для последующего подключения веб-приложения или backend.
- **Оценка RAG** — отдельные инструменты для измерения качества поиска на размеченных контрольных вопросах.

## Запуск на macOS

### 1. Установить Ollama и модель

Установите Ollama с официального сайта: https://ollama.com

Загрузите модель:

```bash
ollama pull qwen3:8b
```

Убедитесь, что сервис Ollama запущен. При необходимости выполните в отдельном окне терминала:

```bash
ollama serve
```

### 2. Установить зависимости

В терминале перейдите в каталог `energytool` и выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Настроить приложение

```bash
cp .env.example .env
```

Для локального запуска значения по умолчанию уже настроены на Ollama и `qwen3:8b`:

```env
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen3:8b
RETRIEVER_MODE=bm25
```

Если используется другая модель, укажите её точное имя в `OLLAMA_MODEL`.

### 4. Запустить чат

```bash
python main.py
```

Перед началом диалога приложение проверит доступность Ollama и наличие выбранной модели. Если модель не установлена или сервис не запущен, приложение выведет причину и инструкцию по устранению ошибки. Ответ от другой модели или заранее подготовленный текст вместо ответа Qwen не подставляется.

Команды чата:

- `/new` — начать новую сессию;
- `/exit` — завершить работу.

## Как работает запрос

1. Пользователь вводит вопрос в терминале.
2. Консультант учитывает предыдущие реплики диалога.
3. RAG ищет подходящие фрагменты в `knowledge-base/`.
4. В контекст модели включаются найденные фрагменты и ограничения соответствующего продукта.
5. Qwen формирует ответ на основе предоставленных материалов.
6. Приложение показывает ответ и идентификаторы найденных источников.

Факты о продуктах, стоимости, сроках и характеристиках должны подтверждаться базой знаний. Если подтверждения недостаточно, консультант сообщает об этом и не формирует неподтверждённые обещания.

## Поиск и эмбеддинги

По умолчанию применяется **BM25** — полноценный лексический алгоритм поиска, работающий локально без внешней поисковой модели. Он не является имитацией LLM: это отдельный поисковый алгоритм, который выбирает документы для контекста Qwen.

Для локального семантического поиска можно дополнительно установить BGE-M3:

```bash
pip install -r requirements-embeddings.txt
```

Затем установить в `.env`:

```env
RETRIEVER_MODE=local
```

При первом запуске загрузится модель BGE-M3; для неё потребуется дополнительное место на диске и время на загрузку. Для воспроизводимого локального запуска без дополнительной модели оставьте `RETRIEVER_MODE=bm25`.

## Оценка качества RAG

`evaluate_retrieval.py` — инструмент контроля качества retrieval, а не этап обработки пользовательского запроса. Он проверяет, попадает ли заранее размеченный правильный фрагмент в верхние позиции поисковой выдачи.

Запуск оценки на локальном BM25:

```bash
python -m rag.evaluate_retrieval --mode bm25
```

Запуск базовой оценки BM25 и сравнение параметров:

```bash
python -m rag.evaluate
```

Основные метрики:

- `hit@1`, `hit@3`, `hit@5`, `hit@10` — доля вопросов, для которых правильный фрагмент найден в первых N результатах;
- `MRR` — средняя обратная позиция первого правильного результата; чем ближе к 1, тем лучше.

Наборы `eval_demo.json`, `eval_own.json` и `eval_dialogs.json` содержат контрольные вопросы и эталонные разделы. Это оценочные данные, они не участвуют в пользовательском диалоге.

## Форматы данных: JSON или CSV

Формат выбирается по структуре данных:

| Данные | Формат | Обоснование |
|---|---|---|
| Исходная база знаний | Markdown | Удобно поддерживать разделы, таблицы и пояснения |
| Размеченные тестовые вопросы | JSON | У вопроса может быть несколько эталонных фрагментов и дополнительные поля |
| Плоские списки вопросов/табличные выгрузки | CSV | Удобно открывать и редактировать в Excel |
| История диалога и состояние сессии | JSON | Сообщения вложены в одну сессию, содержат роли, время и метаданные |
| Подготовленные поисковые фрагменты | JSON | Каждый фрагмент содержит текст и набор метаданных |
| Табличные отчёты | CSV | Удобны для сортировки, фильтрации и анализа |

Переводить всю базу знаний в CSV не рекомендуется: структура Markdown-документов важна для корректного извлечения контекста. JSON подходит для контрольных наборов и структурированных записей, CSV — для плоских таблиц.

## Интерфейс для последующего подключения

Веб-интерфейс и backend-сервер в этой версии не входят в состав проекта. Для интеграции предусмотрен единый интерфейс:

```python
from integration.interface import EnergytoolAI

ai = EnergytoolAI()
result = ai.chat("Расскажите о платформе учёта", session_id=None)

print(result["answer"])
print(result["sources"])
```

Для продолжения диалога передавайте возвращённый `session_id` в следующий вызов. Это позволяет подключить веб-интерфейс позднее без переноса логики RAG и LLM во frontend.

## Проверки перед использованием

```bash
python -m compileall -q .
python -m unittest discover -s tests -v
python -m rag.retrieval "Сколько стоит поиск потерь?" --mode bm25 --short
python -m rag.evaluate_retrieval --mode bm25
```

Автоматические тесты проверяют подготовку базы, работу локального поиска, разбор истории и валидацию интерфейса. Полноценная генерация ответов требует установленной и запущенной Ollama с выбранной моделью; тестовый прогон в среде сборки не заменяет проверку на компьютере с Ollama.

## Ограничения текущей версии

- Работа организована через терминал; веб-интерфейс и backend-сервер подключаются отдельным этапом.
- Интеграция с CRM и фактическая отправка заявок не реализованы.
- Локальные файлы сессий сохраняются без шифрования; перед эксплуатацией с реальными персональными данными требуется защищённое хранилище.
- Качество поиска следует контролировать на актуальном наборе вопросов и эталонных источников.
- Материалы кейса и база знаний не должны публиковаться в открытом репозитории.
